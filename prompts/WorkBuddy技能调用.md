# WorkBuddy 技能调用提示词

本仓库安装为技能后（放到 `~/.workbuddy/skills/lan-portable-deploy/`），以下提示词可直接使用。
技能自带体检脚本与全部模板，因此这些提示词比[通用版](通用智能体提示词.md)短得多。

---

## 标准版（推荐）

```
用 lan-portable-deploy 技能，把这个项目做成能在普通 Windows 电脑上双击运行的版本。

项目路径：D:\你的项目目录
项目名：车间看板（用于生成的文件夹名与说明）

硬性要求：
1. 默认 80 端口对外服务，局域网其他设备只输 http://本机IP/ 就能访问
2. 目标机不装 Node/Python 也能跑 —— 要带便携运行时（--full）
3. 服务崩了自动重启，日志写到 server.log，10 分钟内反复崩溃要止损
4. 数据目录绝不进部署包，升级覆盖代码时不碰数据
5. 产出两样：可直接运行的安装目录 + 一个「一键升级」.bat

执行方式：
- 输出目录先问我要放哪（桌面 / 项目同级 / U 盘），不要自己决定
- 先跑 inspect 体检，把不满足的项逐条列出来（绑定地址、/api/version、数据目录、端口）
- 需要改源码的地方先说明改什么、为什么，等我确认再动
- 构建完把自检结果贴出来；再真跑一次，用 curl 验证 /api/version 和首页
- 最后告诉我：产物路径、本机访问地址、局域网访问地址、防火墙要怎么放行
```

## 一句话版

```
把 D:\你的项目 用 lan-portable-deploy 技能打成 Windows 免安装 + 局域网 80 端口的部署包
```

## 分场景变体

**只要体检、不改动**

```
用 lan-portable-deploy 技能对 D:\你的项目 做只读体检，别改任何文件。
告诉我它现在能不能直接上局域网，不能的话差哪几项、每项怎么改。
```

**纯静态网站**

```
用 lan-portable-deploy 把 D:\my-site 打包：纯静态站，入口 index.html。
技能会自动附带零依赖静态服务器来提供 /api/version 和 80 端口服务。
```

**Python 项目**

```
用 lan-portable-deploy 打包 D:\py-app：入口 app.py，运行时 runtime\python.exe，端口 80。
注意 Python 进程用不了 watchdog.js，稳定性按技能文档里的降级路径处理并说明清楚。
```

**已有部署，只要升级包**

```
用 lan-portable-deploy 给 D:\你的项目 出升级包，不动现有部署：
生成 zip 与「一键升级」.bat，升级时自动定位安装目录、备份、失败回滚，data/ 不许进包。
```

## 触发要点

- **技能名直接点名**：第一句写 `用 lan-portable-deploy 技能`，比描述意图可靠
- **带上关键词**：部署到公司电脑 / 局域网访问 / 80 端口 / 双击运行 / 免安装 / 开机自启
- **明确写死 80 与"零安装"**：默认值虽是 80，写出来能避免它按开发习惯给 8787
- **要求先体检**：否则容易跳过判断直接打包，漏掉"绑在 127.0.0.1"这类根本问题
