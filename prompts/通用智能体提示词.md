# 通用智能体提示词

## 一、短版（推荐）

规范不写进提示词，让它自己去仓库读。适合**能联网、能读网页或 clone 仓库**的智能体。

```
读取 https://github.com/zhangdunlong/lan-portable-deploy 的 SKILL.md 与 references/ 全篇，
按其中的规范把下面这个项目改造成「Windows 免安装、双击即跑、局域网可访问（默认 80 端口）」的部署形态。

项目路径：D:\你的项目
项目名：你的项目名
运行时：node（或 python）

流程要求：
1. 先体检，逐条列出不满足项（绑定地址 / 端口 / /api/version / 数据目录 / 依赖），等我确认后再改源码
2. 硬约束以 references/lan-readiness.md、references/windows-encoding.md 为准，不要自行简化或省略
3. 构建后自检，并真跑一次给出证据：/api/version 返回版本、首页 200、用局域网 IP 也能访问
4. 最后告诉我产物路径、访问地址、防火墙放行方法
```

## 二、极短版（一句话）

```
按 https://github.com/zhangdunlong/lan-portable-deploy 的规范，把 D:\你的项目 改造成 Windows 免安装 + 局域网 80 端口部署；先体检，改完自检给证据。
```

## 三、让它直接抓原始文件（更省 context）

把这些地址给它，比让它解析仓库页面更可靠：

```
https://raw.githubusercontent.com/zhangdunlong/lan-portable-deploy/main/SKILL.md
https://raw.githubusercontent.com/zhangdunlong/lan-portable-deploy/main/references/lan-readiness.md
https://raw.githubusercontent.com/zhangdunlong/lan-portable-deploy/main/references/port80-and-firewall.md
https://raw.githubusercontent.com/zhangdunlong/lan-portable-deploy/main/references/windows-encoding.md
https://raw.githubusercontent.com/zhangdunlong/lan-portable-deploy/main/references/troubleshooting.md
https://raw.githubusercontent.com/zhangdunlong/lan-portable-deploy/main/references/layout.md
```

> `raw.githubusercontent.com` 在国内常被拦。打不开就在地址前加代理，例如
> `https://gh-proxy.com/https://raw.githubusercontent.com/...`，或直接给仓库页面链接让它自己找。

## 四、能执行命令的环境（让它自己把模板拉下来用）

```
git clone https://github.com/zhangdunlong/lan-portable-deploy.git
按该仓库 SKILL.md 的五步流程，把 D:\你的项目 改造成 Windows 便携局域网部署；
模板直接用仓库 assets/ 里的，不要自己重写。
```

## 附录：内联长版（离线 / 智能体读不到仓库时用）

当对方**不能联网、也不能 clone**（内网模型、纯对话界面）时，把下面整段贴给它，规范已全部内联。

```
【任务】把指定项目打包成「普通 Windows 电脑免安装、双击即跑、局域网可访问（默认 80 端口）」的部署形态。

项目路径：<填绝对路径>
项目名：<填显示名>
运行时：<node 或 python>

【第一步：先体检，不要直接开始写文件】
检查并逐条报告：
1) 监听地址是否绑 0.0.0.0（绑 127.0.0.1 或 localhost = 局域网访问不到，必须改）
2) 端口是否从环境变量读（PORT），默认值是否为 80
3) 是否提供 /api/version，返回 {"version":"vX.Y.Z"}
4) 业务数据是否在独立目录（如 data/），与代码分离
5) 是否有第三方依赖、能否用语言内置模块替代
把不满足的项连同「需要改哪个文件、怎么改」一起告诉我，等我确认后再动源码。

【硬性约束（违反即返工）】
· 数据目录绝不进部署包；升级覆盖代码时不得触碰数据
· .bat 必须 GBK 编码 + CRLF 换行（cmd 按 ANSI 解码，UTF-8 会中文乱码）；文件内先写 chcp 936
· .ps1 必须 UTF-8 带 BOM，且只能有一个 BOM（PowerShell 5.1 靠 BOM 认 UTF-8，缺了整段解析失败）
· 单文件自解压 .bat：base64 数据段之前必须有 exit /b 0，否则 cmd 会把 base64 当命令执行并刷屏
· 版本号只允许一个来源（入口文件的 APP_VERSION），打包脚本只读不写
· 停止服务按端口定位进程，禁止 taskkill /f /im node.exe（会误杀同机其他程序）

【80 端口】
· 默认 80，局域网只输 http://本机IP/ 即可
· 启动脚本先探测占用：被占用时列出占用进程（PID + 进程名），允许改用 8080
· 实际端口写入 _port.txt，停止与升级脚本都读它（否则会出现「升级成功但版本没变」）
· 提示用户：拿回 80 用管理员执行 net stop http；查占用 netstat -ano | findstr :80

【产物结构】
<输出目录>/
├── <项目名>/                 安装目录，双击 启动.bat 即运行
│   ├── <入口> <静态目录>/ data/(空) runtime/
│   ├── 启动.bat 停止.bat 防火墙放行.bat 开机自启.bat
│   ├── watchdog.js  setup.ps1  version.txt  安装说明.txt
└── 部署包/
    ├── <项目名>_升级包_v<版本>_<日期>.zip
    └── <项目名>_一键升级_v<版本>_<日期>.bat   单文件自解压，双击即装

【启动/停止/守护】
· 启动：选运行时（优先 runtime/）→ 查端口 → 写 _port.txt → 用 VBS 隐藏窗口拉起 → 等端口就绪 → 开浏览器
· 停止：写 _stop.flag → 停守护进程 → 按端口停服务 → 清标志（顺序不能反，否则守护会把服务拉回来）
· 守护 watchdog：崩溃 2 秒后重启、日志 5MB 轮转、10 分钟内崩 20 次则写「_崩溃过多.txt」并止损

【安装/升级引擎】
① 定位安装目录：注册表 → 包内 → 常见位置打分扫描（runtime +5 / 数据文件 +4 / 入口 +1）→ 弹框手选；
   %TEMP% 内路径一律不作候选（否则会把自己当安装目录，Copy-Item 报 "with itself"）
② 备份入口与静态目录到 _升级备份_<时间戳>/，只留最近 3 份
③ 按端口停服（端口取自 _port.txt）
④ 覆盖：入口直接换；静态目录先拷成 <目录>.__new__ 再原子改名
⑤ 经隐藏启动脚本重启（保住端口环境变量）
⑥ 轮询 /api/version 校验版本一致；不一致要提示，不能当成功
⑦ 任何一步失败自动回滚并重启旧版本
⑧ 注册表记住安装位置

【交付前自证】
1) 自检：结构完整、.bat 是合法 GBK+CRLF、.ps1 只有单个 BOM、zip 不含 data/、自解压 payload 还原后与原 zip 逐字节一致
2) 真跑：/api/version 返回版本、首页 200
3) 局域网：用本机局域网 IP（不是 127.0.0.1）curl 一次，返回 200
4) 守护：杀掉服务进程，2~3 秒内自动换新 PID 恢复
5) 汇报：产物路径、本机/局域网地址、防火墙放行方法、如何停止与开机自启

【做不到就直说】哪项没做到、原因、替代方案，不要用「已完成」糊过去。
```

**若对方不能执行命令**（纯对话模型），在末尾加：
`你无法执行命令，请直接输出全部文件的完整内容，按上面结构给出每个文件的路径与代码。`
