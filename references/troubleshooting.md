# 现场故障速查（症状 → 根因 → 处理）

按"现场看到的现象"索引。每条都给可执行的判定命令，不要靠猜。

---

## A. 双击「启动.bat」窗口一闪就没了

| 可能根因 | 判定 | 处理 |
|---|---|---|
| 运行时不存在的分支走到了 `exit /b 1` | 命令行手动跑一遍 `启动.bat`，看提示 | 把 `runtime\node.exe` 放进安装目录，或装 Node |
| `.bat` 编码坏了，cmd 解析错乱 | 用记事本打开，中文是否乱码 | 重新构建（构建脚本会强制 GBK+CRLF） |
| 端口被占用走了 `PORT_BUSY` 分支 | 窗口里应有占用进程列表 | 关占用程序，或按回车用 8080 |

> 排查技巧：把 `启动.bat` 拖到 `cmd` 窗口里回车运行，窗口不会关，能看到完整输出。

---

## B. 本机能开，别的电脑打不开

按这个顺序判定，别跳步：

```bat
REM 1. 本机按 127.0.0.1 能不能开
curl http://127.0.0.1/api/version

REM 2. 本机按局域网 IP 能不能开（这一步能验出「绑在 127.0.0.1」）
curl http://<本机IP>/api/version

REM 3. 另一台电脑 ping 本机
ping <本机IP>
```

| 结果组合 | 根因 | 处理 |
|---|---|---|
| 1 通、2 不通 | 服务绑在 `127.0.0.1` | 改代码绑 `0.0.0.0`（改造清单第 1 条） |
| 1、2 通，3 的 curl 不通但 ping 通 | 防火墙拦入站 | 管理员运行「防火墙放行.bat」 |
| 1、2 通，3 的 ping 也不通 | 网络层不通 | 查是否同网段 / 无线隔离 / 交换机 VLAN |
| 1 都不通 | 服务没起 | 看 `server.log` |

## C. 端口被占用（`EADDRINUSE` / 启动器提示占用）

```bat
netstat -ano | findstr :80
tasklist | findstr <PID>
netsh http show servicestate
```

- PID = 4 或指向 `System` → http.sys 预留，管理员 `net stop http`
- PID 指向具体程序 → 关掉它
- 实在腾不出来 → 按回车用 8080，并告知使用者访问地址要带 `:8080`

## D. 服务起来又自己停 / 停不掉

| 症状 | 根因 | 处理 |
|---|---|---|
| 双击「停止.bat」后过几秒又活了 | 守护进程还在，把子进程重新拉起来了 | 脚本应先写 `_stop.flag` 再杀守护（已内置）；若手动 kill 端口，必须同时 kill 守护 |
| 停止后一直起不来 | 遗留了 `_stop.flag` | 删掉安装目录里的 `_stop.flag` 再启动 |
| 反复重启刷日志，目录里多了 `_崩溃过多.txt` | 服务启动即崩 | 看 `server.log` 里第一条错误；常见是端口占用、数据文件损坏、依赖缺失 |

**手动停干净的两步**（顺序不能反）：

```powershell
# 1. 先给守护发停止信号
"stop" > _stop.flag
# 2. 再结束守护与子进程（按命令行/端口定位，别全局 taskkill node.exe）
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*watchdog.js*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

## E. 升级提示成功，但版本号没变

四个可能，按概率排序：

1. **端口不一致**：服务实际跑在 8080，引擎按 80 去停服/校验 → 检查 `_port.txt` 与 `-Port` 参数
2. **改的是旧目录**：机器上装了两份，升级覆盖了另一份 → 看注册表 `InstallDir` 或升级日志里的目录
3. **浏览器缓存**：`Ctrl+Shift+R` 强刷再看
4. **版本号没跟着改**：入口文件的 `APP_VERSION` 与页面显示的不一致 → 直接 `curl /api/version` 看服务真实返回

---

## F. 页面能开但样式/脚本是旧的

- 确认静态资源带了版本戳 `?v=`；不带的资源走 `no-store`
- 升级后必须强刷一次（旧文档还持有旧 CSS/JS 的内存副本）
- 检查是不是被反向代理/网关缓存了

---

## G. 中文全是问号或方块

- `.bat` 里：文件不是 GBK 写的 → 重新构建
- PowerShell 输出到日志：没设 `[Console]::OutputEncoding` → 设 UTF8
- 页面里：HTTP 响应头缺 `charset=utf-8`，或 HTML 缺 `<meta charset>`
- 说明文件：`.txt` 没带 BOM，老记事本按 GBK 读 → 加 BOM

## H. 杀毒软件拦截

**现象**：双击后提示"无法复制到临时目录"、"找不到文件"、升级中途退出。

**根因**：`%TEMP%` 下解压并执行 `.ps1` 的行为，与某些杀软/EDR 的启发式规则冲突。

**处理**

- 把安装目录加入杀软白名单
- 或在组策略/EDR 里放行 `powershell.exe -ExecutionPolicy Bypass -File <安装目录>\setup.ps1`
- 应急：手工解压 zip，双击里面的「安装.bat」

> 这一条在实际工厂环境出现频率不低，部署前先问一句"这台机器有没有装公司统一的杀毒/管控软件"。

## I. 机器重启后服务没起来

- 未注册开机自启 → 双击「开机自启.bat」；它往启动文件夹放快捷方式，**登录该 Windows 账号时**才触发（不是开机即启，不需要管理员）
- 若要求"开机即启、无人登录也在跑"，改用计划任务（触发器选"计算机启动时"，勾选"不管用户是否登录"，运行账户填 SYSTEM）
- 服务起来了但访问不了 → 回到 B 节
